# R6-D: World-Model Ablation — Locked (per plan)

Date: 2026-08-10  
Status: LOCKED.  The R6-D world-model ablation is not run until the no-WM
R6-C.1 gate passes on both VLAs.

## Plan requirement (R6-D postposed)

From the revised plan: R6-D (action-conditioned multi-step latent residual +
dynamics ensemble disagreement, as additional features only) unlocks **only
after** the dual-VLA no-WM R6-C.1 stage gate passes (>=4/5 seeds per VLA on the
early-window stratified selector).  Until then, the WM ablation stays sealed and
must be reported as a negative/not-run ablation, not as an alternative main
method.

## Pre-registered infrastructure (ready, not run)

- `scripts/cache_r6d_wm_features.py` — real-frame-aligned residual/disagreement
  feature cache for the B1.2 boundaries (side-effect-free replay; boundary frame
  pixel check; `--exclusions` support).
- `scripts/run_r6d_wm_oof.sh` — re-runs the candidate-arm OOF with
  `--wm-features` and per-seed/per-VLA Pareto comparison against the no-WM
  baseline.
- `scripts/eval_r6d_wm_ablation.py` — pre-registered state-level Pareto gate
  (AUROC gain >= 0.02, dominant on >=4/5 seeds, per-VLA).
- Model side: `CandidateArmStudent.wm_proj` (66->32) already implements the
  "additional feature stream, never a pooled-latent replacement" rule.
- Smoke path `runs/smoke_r6d_wm_path/` validates the plumbing end to end.

## Unlock conditions (all must hold)

1. R6-C.1 no-WM gate passes on pi0fast_libero AND pi05_libero (>=4/5 seeds,
   fold-correct success gap >= -5pp, false-continue <= 5%, absolute paired harm
   <= 5%, savings >= 20%, no suite-concentrated harm).
2. WM features give a state-level Pareto gain on BOTH VLAs (risk ranking,
   calibration, success/harm/savings, latency and memory acceptable).
3. Otherwise: R6-D is written up as a negative ablation and the WM arm exits
   the main method.

## Current evidence

The original R6-C no-WM baseline failed its 5-seed gate (0/5); the R6-C.1B
data re-collection and R6-C.1C early-window selector are the current attempt to
build a no-WM baseline that passes.  Per the plan decision tree, WM is not the
fix for missed switch timing, so it is deliberately kept out until a no-WM
controller is established.
