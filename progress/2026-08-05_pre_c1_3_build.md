
This is a controlled data-ablation study on the Recovery LoRA path. It does NOT replace the frozen-VLA stale-suffix invalidation gate.

## Scientific Question

Does position-weighted OFT teacher-suffix replay, added to C1.1 warm-started continued fine-tuning, preserve mid-horizon state recoverability and improve student self-recovery versus student-query-only retraining, without degrading clean behavior?

## Key Design Decisions

1. **Not exact resume**: Only C1.1 `adapter_final` weights are available (no optimizer state). Training loads C1.1 LoRA weights onto fresh base, re-initializes Adam.

2. **Matched optimizer steps (500), not epochs**: Arms A'/B/C have different dataset sizes (333/380/603 train rows). All arms trained for exactly 500 optimizer steps.

3. **Suffix coverage limitation**: The DAgger protocol only recorded 2 suffix chunks per query. Consequently, the Arm C dataset only has offset-1 and offset-2 suffix states. The position-weighted corridor sampling cannot meaningfully differentiate early/mid/late positions. The experiment can still test whether ANY suffix data helps, but cannot distinguish position-weighted from uniform sampling.

4. **Training seeds**: 3 per arm. Single training seed can produce meaningfully different LoRA results.

## Anticipated Interpretations

Given the suffix data limitation (only offset 1-2), the experiment is a stronger test of "any suffix" vs "no suffix" than of "recovery corridor" vs "tube entrance." An Arm C advantage would be evidence that even brief teacher suffix frames help maintain recoverability.
